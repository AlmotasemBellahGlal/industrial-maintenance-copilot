# Manual knowledge pipeline

Register `AddLlmProviders(configuration)` then `AddKnowledgePipeline(configuration)`.
The host resolves `ManualIngestionService`, `IRetrievalService`, and `IKnowledgeIndex`.
Run `KnowledgeSchema.ApplyAsync(token)` explicitly during deployment, using a
connection/role allowed to create the vector extension and knowledge schema.
The idempotent initial SQL migration is embedded as `Migrations/001_knowledge.sql`.
It stores only knowledge profiles, revisions, chunks, text and vectors.

Non-secret configuration, in addition to the existing Llm section:

```json
{
  "Knowledge": {
    "EmbeddingProfile": "maintenance-embeddings-v1",
    "EmbeddingRevision": "deployment-pinned-weights-and-preprocessing-v1",
    "Dimensions": 1536,
    "ChunkSize": 1200,
    "Overlap": 200,
    "HybridCandidates": 100
  }
}
```

Supply `ConnectionStrings__Knowledge` through environment/user secrets or a
deployment secret provider. Never commit a database password. Dimensions must
match the selected embedding model, not this example. Pin model weights and
preprocessing; change EmbeddingProfile and reingest when either changes. The
immutable database profile binding rejects accidental provider/model/endpoint/
revision changes under an existing profile, including equal-dimensional spaces.
The returned embedding model is checked; missing model identity fails closed.

`IngestAsync(request, source, token)` accepts only UTF-8 text/plain (optional
charset=utf-8). Raw PDFs, OCR and other media fail explicitly. Streams need not
seek and remain caller-owned. Chunk size/overlap count Unicode scalars; locators
contain source line and scalar ranges. Content is retained verbatim except for
an initial UTF-8 BOM. Empty extraction leaves existing knowledge unchanged.
The current text limit is four million UTF-16 characters.

Embedding generation uses ILlmProvider in batches; only a fully validated batch
set reaches the atomic revision replacement. Queries select the configured
profile; explicit document/revision filters containing another profile fail
clearly. Unfiltered queries search only the configured profile. Full-text,
cosine, and hybrid results carry complete chunk text as Snippet plus all IDs and
the original locator. Dense similarity below zero is excluded by default;
hybrid uses equal-weight RRF (k=60), with at least TopK candidates from each mode.

No manual text, vectors, connection strings, or database error details are
logged by this implementation. SQL values are parameters. The binding is a
configuration compatibility check, not proof that arbitrary caller-supplied
vectors were generated by the model.

Integration tests require `RAG_TEST_POSTGRES` pointing at an isolated test
PostgreSQL/pgvector server with permission to create databases. Each test class
creates and drops only its own generated database. CI provisions a disposable
pgvector container. Without this variable, storage tests are explicitly skipped;
all other tests run offline. Production connections must never be used for tests.
