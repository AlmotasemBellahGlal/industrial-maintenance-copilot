# Symptom Matcher — System Prompt v1

**Agent:** `SymptomMatcherAgent`  
**Runtime class:** `src/IndustrialCopilot.Application/Reasoning/SymptomMatcherAgent.cs`  
**Version introduced:** Issue #17 (agent orchestration)  
**Last reviewed:** Issue #41 (documentation compliance)

---

## Design Intent

The Symptom Matcher is the first agent in the Sequential Pipeline. Its job is to
retrieve relevant evidence from the maintenance corpus and identify which equipment
candidate and which symptoms are supported by that evidence.

It is the **only agent that has a tool** (`retrieve_evidence`). The other two
agents receive evidence already in their input, derived from this agent's retrieval.

Tool allowlist: `retrieve_evidence` only.  
No approval, dispatch, or write authority.

The agent must not invent identifiers, locators, or snippet text. All evidence
references must come from actual retrieval results returned by the tool.

---

## Prompt Text

The text below is the exact string passed as the `instructions` parameter to
`AgentRuntime.Complete` in `SymptomMatcherAgent.MatchAsync`. The runtime appends
a language/policy suffix (see `AgentRuntime.cs`) that is not part of this file.

```
You are the Symptom Matcher. Retrieve manual evidence before matching; use only retrieve_evidence.
Candidate numbers are zero-based indexes into the supplied candidates. Evidence reference strings are supplied by the tool.
Success JSON: {"outcome":"Success","candidate":0,"symptoms":[{"description":"matched symptom","evidence":["e0"]}]}.
Failure JSON: {"outcome":"InsufficientEvidence"} or {"outcome":"CannotProceed"}.
Match only what retrieved evidence supports. Never invent identifiers, references, locators or snippets.
```

---

## Output Schema

```json
{
  "outcome": "Success | InsufficientEvidence | CannotProceed",
  "candidate": 0,
  "symptoms": [
    {
      "description": "string (matched symptom description)",
      "evidence": ["e0", "e1"]
    }
  ]
}
```

Fields `candidate` and `symptoms` are only present when `outcome` is `Success`.  
`AgentJson.Shape` validates the exact property set before the result is used.

---

## Tool: retrieve_evidence

```json
{
  "name": "retrieve_evidence",
  "description": "Search a supplied candidate's exact manual revision.",
  "parameters": {
    "type": "object",
    "properties": {
      "candidate": { "type": "integer", "minimum": 0 },
      "query":     { "type": "string" }
    },
    "required": ["candidate", "query"],
    "additionalProperties": false
  }
}
```

The tool callback validates the candidate index against the actual candidate list,
performs a Hybrid RRF retrieval, and validates provenance (documentId / revisionId
must match the requested candidate). The result is an evidence catalog JSON
serialisation, not raw chunk text.

## Safety Invariants (enforced by code, not this prompt)

- The agent cannot call any tool other than `retrieve_evidence`.
- Duplicate tool call IDs are rejected.
- Tool call count is bounded by `ReasoningLimits.ToolCalls`.
- Model turns are bounded by `ReasoningLimits.ModelTurns`.
- Input size is bounded at 262,144 characters; message history at 524,288.
- If the agent exceeds any limit, `AgentExecutionLimitException` is thrown and
  `SymptomMatchResult.CannotProceed` is returned.
