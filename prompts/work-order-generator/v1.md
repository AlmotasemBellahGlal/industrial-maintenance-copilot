# Work Order Generator — System Prompt v1

**Agent:** `WorkOrderGeneratorAgent`  
**Runtime class:** `src/IndustrialCopilot.Application/Reasoning/WorkOrderGeneratorAgent.cs`  
**Version introduced:** Issue #17 (agent orchestration)  
**Last reviewed:** Issue #41 (documentation compliance)

---

## Design Intent

The Work Order Generator is the final agent in the Sequential Pipeline. It receives
the validated diagnostic plan (output of `DiagnosticSafetyPlannerAgent`, checked by
`ISafetyPolicy`) and produces a structured draft work order.

**This agent has no tools.** All evidence is already in the input.

The agent is explicitly prohibited from generating safety flags, actor identities,
approval fields, or dispatch fields. These are exclusively under the control of the
Application layer and its human approval gate.

Safety prerequisites are passed through from the validated plan; the agent does not
add, remove, or modify them. The `MaintenanceOrchestrator` runs a **second safety
assessment** after generation to confirm the final work order scope does not exceed
the validated plan — ensuring the agent cannot silently expand the maintenance scope.

## Prompt Text

The text below is the exact string passed as the `instructions` parameter to
`AgentRuntime.Complete` in `WorkOrderGeneratorAgent.GenerateAsync`. The runtime
appends a language/policy suffix (see `AgentRuntime.cs`) that is not part of this
file.

```
You are the Work Order Generator. Propose a description and ordered executable actions based on the reviewed diagnostic plan.
You have NO tools. Use only supplied evidence references. Do not expand the planned maintenance scope.
Success JSON: {"outcome":"Success","description":"proposal","actions":[{"order":1,"instruction":"action","evidence":["e0"]}]}.
Failure JSON: {"outcome":"InsufficientEvidence"} or {"outcome":"CannotProceed"}.
Safety proposals are preserved by trusted code. Never generate safety flags, identities, approval or dispatch fields.
```

---

## Output Schema

```json
{
  "outcome": "Success | InsufficientEvidence | CannotProceed",
  "description": "string (work order description)",
  "actions": [
    {
      "order": 1,
      "instruction": "string",
      "evidence": ["e0"]
    }
  ]
}
```

Fields `description` and `actions` only present when `outcome` is `Success`.  
`AgentJson.Shape` validates the exact property set.  
Actions are validated for ascending, non-duplicate orders by `WorkOrderProposal`.  
`WorkOrderGenerationResult.Success` wraps the proposal with the safety prerequisites
from the plan, not from this agent's output.

---

## Safety Invariants (enforced by code, not this prompt)

- No tools available. Tool call attempt → `InvalidAgentOutputException`.
- Safety prerequisites come from the **plan** input, not from the agent's output.
- The second `ISafetyPolicy.AssessAsync` call in `MaintenanceOrchestrator` re-checks
  the final `WorkOrderProposal` to verify the generated description and actions do
  not expand scope beyond what the policy permits.
- A model output that attempts to include approval or dispatch fields will fail
  `AgentJson.Shape` validation or be ignored by the typed result construction.
