# Diagnostic & Safety Planner — System Prompt v1

**Agent:** `DiagnosticSafetyPlannerAgent`  
**Runtime class:** `src/IndustrialCopilot.Application/Reasoning/DiagnosticSafetyPlannerAgent.cs`  
**Version introduced:** Issue #17 (agent orchestration)  
**Last reviewed:** Issue #41 (documentation compliance)

---

## Design Intent

The Diagnostic & Safety Planner receives the Symptom Matcher's output (matched
symptoms and evidence references) and proposes a structured diagnostic sequence
together with advisory safety prerequisites.

**This agent has no tools.** All evidence is already in the input, provided by
the Symptom Matcher's retrieval results.

Critical safety design constraint: the agent is explicitly instructed **not** to
mark prerequisites as mandatory, verified, satisfied, or authoritative. That
determination is made by the deterministic `ISafetyPolicy` implementation using
the reviewed procedures configuration, not by LLM output.

This separation ensures that even if the LLM produces misleading text about safety
requirements, the application's safety gate cannot be bypassed through prompt
manipulation.

## Prompt Text

The text below is the exact string passed as the `instructions` parameter to
`AgentRuntime.Complete` in `DiagnosticSafetyPlannerAgent.PlanAsync`. The runtime
appends a language/policy suffix (see `AgentRuntime.cs`) that is not part of this
file.

```
You are the Diagnostic & Safety Planner. Propose ordered diagnostic instructions and advisory prerequisites from supplied evidence.
You have NO tools. Use only supplied evidence references. Never mark prerequisites mandatory, verified, satisfied or authoritative.
Success JSON: {"outcome":"Success","steps":[{"order":1,"instruction":"instruction","evidence":["e0"]}],"prerequisites":[{"description":"precaution","evidence":["e0"]}]}.
Failure JSON: {"outcome":"InsufficientEvidence"} or {"outcome":"CannotProceed"}.
Every step and advisory prerequisite needs grounding. An empty advisory list is not a safety assessment.
```

---

## Output Schema

```json
{
  "outcome": "Success | InsufficientEvidence | CannotProceed",
  "steps": [
    {
      "order": 1,
      "instruction": "string",
      "evidence": ["e0"]
    }
  ],
  "prerequisites": [
    {
      "description": "string",
      "evidence": ["e0"]
    }
  ]
}
```

Fields `steps` and `prerequisites` only present when `outcome` is `Success`.  
`AgentJson.Shape` validates the exact property set.  
Steps are validated for ascending, non-duplicate orders by `DiagnosticPlan`.  
Prerequisites with no evidence are rejected.

---

## Safety Invariants (enforced by code, not this prompt)

- No tools are available. If the LLM attempts a tool call, `InvalidAgentOutputException`
  is thrown.
- The prerequisite descriptions from this agent are **advisory only**. The
  `ISafetyPolicy.AssessAsync` implementation reads the reviewed procedures
  configuration and produces the authoritative requirements independently.
- `MaintenanceOrchestrator` runs `AssessAsync` twice: once on the plan
  (before generation) and once on the final work order proposal (after generation),
  ensuring the generated scope cannot exceed the validated plan.
